# Кабинет клиента

Отдельное приложение для клиента поставщика: витрина, корзина, свои заявки
и шаблоны. Собирается в статику (Vite + React) и отдаётся nginx — своим образом
и своим тегом, независимо от рабочего места менеджера и от бэкенда.

## Разработка

```bash
npm ci
npm run dev      # http://localhost:5174
npm run test     # vitest
```

Dev-сервер сам проксирует `/api` и `/actuator` на бэкенд из `VITE_DEV_API_TARGET`.
Прокси убирает правило источников по существу: браузер видит запрос
на собственный origin страницы.

Настройки берутся из `.env` (см. переменные `VITE_*`). Файла-образца нет
намеренно: второй список переменных расходится с первым на первой же новой
строке, и обнаруживается это отказом стенда.

## Сборка образа

Адреса окружения нужны **на сборке**: Vite подставляет `import.meta.env`
в код, и в готовой статике переменных уже нет — менять их в рантайме нечему.
Поэтому разные стенды означают разные сборки.

```bash
docker build -t fastorders/portal:latest \
  --build-arg VITE_API_URL= \
  --build-arg VITE_KEYCLOAK_URL=http://localhost:8081 \
  --build-arg VITE_KEYCLOAK_REALM=fastorders-customers \
  --build-arg VITE_KEYCLOAK_CLIENT_ID=fastorders-portal \
  .
```

Пустой `VITE_API_URL` — не забытое значение: в образе кабинет и API отдаются
одним nginx, и относительный адрес избавляет от правила источников целиком.
Значения выше совпадают с умолчаниями `Dockerfile` — при сборке для другого
стенда меняется адрес Keycloak, остальное остаётся.

## Запуск в окружении

Сервис `portal-web` описан в `docker-compose.yml` бэкенда, профили `app` и `full`:

```bash
docker compose --profile app up -d portal-web   # http://localhost:5174
```

Порт на хосте задаёт `PORTAL_PORT` и он обязан совпадать с адресом
из `PORTAL_BASE_URL` (из него собирается ссылка приглашения) и с адресами
возврата клиента `fastorders-portal` в realm `fastorders-customers`.

## Маршруты внутри контейнера

| Адрес | Куда идёт |
|---|---|
| `/api/…` | прокси на `fastorders-api:5000` |
| `/actuator/info`, `/actuator/health` | туда же: по ним кабинет отличает недоступный бэкенд от своей ошибки |
| `/actuator/…` прочее | 404: метрики читает Prometheus внутри сети, в браузере им делать нечего |
| `/assets/…` | файлы сборки с хэшем в имени, кэш на год |
| всё остальное | `index.html`: маршруты кабинета разбирает браузер |
