# Кабинет клиента

Отдельное приложение для клиента поставщика: витрина, корзина, свои заявки
и шаблоны. Собирается в статику (Vite + React) и отдаётся nginx отдельным
образом, независимо от рабочего места менеджера и от бэкенда.

> **Документация — в репозитории бэкенда:**
> [`back/qorder/docs/portal.md`](../../back/qorder/docs/portal.md) — устройство,
> экраны, состояние работ, сборка образа, правила. Здесь — только то, что нужно,
> чтобы запустить и собрать.

## Разработка

```bash
npm ci
npm run dev        # локальный API, http://localhost:5174
npm run dev:stand  # API стенда test через Vite proxy
npm run test       # vitest
npm run build      # tsc -b && vite build
```

Dev-сервер сам проксирует `/api` и `/actuator` на бэкенд из `VITE_DEV_API_TARGET`.
Прокси убирает правило источников по существу: браузер видит запрос
на собственный origin страницы. `npm run dev:stand` включает режим `stand` и
берёт цель `http://portal-test.q-order.kz` из репозиторного `.env.stand`;
`VITE_API_URL` там намеренно пуст, поэтому браузер продолжает ходить через Vite.

Локальные настройки берутся из `.env` (переменные `VITE_*`), настройки режима
стенда — из `.env.stand`. В обоих файлах только публичная браузерная
конфигурация, секреты в них хранить нельзя.

## Контракт

```bash
npm run api:pull       # снять openapi.json с бэкенда (/v3/api-docs)
npm run api:generate   # перегенерировать клиента (orval)
```

## Runtime-конфигурация образа

Один и тот же образ используется во всех окружениях: адреса стенда не передаются
через Docker build args и не запекаются в сборку Vite. При старте контейнера
переменные `APP_*` из ConfigMap записываются entrypoint-скриптом в `/config.js`,
который приложение загружает до основного JavaScript. `APP_API_URL` может быть
пустым — тогда запросы идут на тот же origin и nginx проксирует их на адрес из
`NGINX_API_UPSTREAM`.

ConfigMap для test и preprod находятся в `.infra/configmap/`. Это публичные
настройки браузера и nginx; секреты в ConfigMap и `config.js` не допускаются.
Образ выбирается в Helm неизменяемым `image.digest`, а `rolloutRevision` меняет
шаблон пода и гарантирует его пересоздание после обновления конфигурации.

Для локального контейнера остаётся команда:

```bash
docker compose --profile app up -d portal-web   # http://localhost:5174
```
