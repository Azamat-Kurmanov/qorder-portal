# Кабинет клиента

Отдельное приложение для клиента поставщика: витрина, корзина, свои заявки
и шаблоны. Собирается в статику (Vite + React) и отдаётся nginx — своим образом
и своим тегом, независимо от рабочего места менеджера и от бэкенда.

> **Документация — в репозитории бэкенда:**
> [`back/qorder/docs/portal.md`](../../back/qorder/docs/portal.md) — устройство,
> экраны, состояние работ, сборка образа, правила. Здесь — только то, что нужно,
> чтобы запустить и собрать.

## Разработка

```bash
npm ci
npm run dev      # http://localhost:5174
npm run test     # vitest
npm run build    # tsc -b && vite build
```

Dev-сервер сам проксирует `/api` и `/actuator` на бэкенд из `VITE_DEV_API_TARGET`.
Прокси убирает правило источников по существу: браузер видит запрос
на собственный origin страницы.

Настройки берутся из `.env` (переменные `VITE_*`). Файла-образца нет намеренно:
второй список переменных расходится с первым на первой же новой строке,
и обнаруживается это отказом стенда.

## Контракт

```bash
npm run api:pull       # снять openapi.json с бэкенда (/v3/api-docs)
npm run api:generate   # перегенерировать клиента (orval)
```

## В окружении

```bash
docker compose --profile app up -d portal-web   # http://localhost:5174
```

Адреса окружения нужны **на сборке** образа — Vite подставляет их в код,
и в готовой статике менять нечего. Команда сборки образа и таблица переменных —
в [`portal.md`](../../back/qorder/docs/portal.md) §14.
